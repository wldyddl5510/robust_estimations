# Non-sparse estimators and SDP reference implementations

`non_sparse_algorithm.non_sparse_estimation` runs Algorithm 1 without the outer support-selection MIP. Setting s=d already makes the original Algorithm 1 non-sparse. After the full-support block-rule correction, both implementations use complexity d and the same K/partition; they differ in solver path, not block construction. For s<d, the shared default remains s*log(d/s). The hybrid separation heuristics and objective-gap certificates are retained. Sanity check 21 is a historical run made before this correction; its frozen sources and recorded settings remain available.

`depersin_lecue.depersin_lecue_estimation` implements the outer covSDPofMeans routine of [Depersin–Lecué, arXiv:1906.03058](https://arxiv.org/abs/1906.03058). Its covering problem is

    min tr(M) + sum(y), M >=PSD 0, y >= 0,
    rho * z_i.T @ M @ z_i + 0.9*K*y_i >= 1.

Two explicitly named backends share that outer routine:

- `backend="clarabel"`: CVXPY/Clarabel general SDP control. Primal PSD/nonnegativity correction and constraint scaling give a feasible covering upper bound; normalized constraint duals give a feasible packing lower bound. The relative gap is checked against `sdp_eta`.
- `backend="ptz"`: `positive_sdp.py` implements the multiplicative decision updates in [Peng–Tangwongsan–Zhang, Algorithm 3.1](https://arxiv.org/abs/1201.5135), with binary objective search. This does not call a general SDP solver. Matrix exponentials use the factorized Taylor expansion from Section 4 and exploit the rank-one/diagonal blocks. At small d, an identity sketch avoids JL error. Dense d-by-d accumulation and eigenvalue certificates remain: **this is a small-d implementation of the specialized solver, not a complete high-dimensional nearly-linear implementation**.

The PTZ accuracy is eta=1e-4, used by DL's [0.9981,1] acceptance interval. The current internal decision accuracy is eta/20, as requested after the original eta/40 runs. The PTZ packing loss 1/(1+10*epsilon) matches the wrapper threshold 1/(1+eta/2) at epsilon=eta/20; this divisor is an implementation calibration, not a paper-prescribed constant. The update size is alpha=(epsilon/H)/(1+10*epsilon), H=(1+ln K)/epsilon. At K=41 the current alpha is 5.303568e-12. This update rate is separate from the contamination fraction and e_tol. The current default cap is 200,000 updates per decision call. Missing certificates at the cap are marked nonconverged. No generic solver is substituted, and the initial estimate is not reported as a completed PTZ estimate. Original experiments retain their frozen eta/40, 100,000-update sources and records. The exponentiation range guard, certification rules, final relative-gap requirement, and other solver parameters are unchanged.

DL implementation conventions: use actual block averages, retain all samples in balanced blocks, choose the conservative outer iteration bound from Algorithm 1's square-root denominator (Algorithm 4's displayed denominator differs), and use ceil(log2(1e9*d**4)) bisection steps. The outer fallback is the paper's initial/current-center return rule. Such a return is not a statistical accuracy certificate when the theorem assumptions fail. `tol` controls numerical SDP tolerances; it does not replace DL's fixed eta.

`cherapanamjeri_flammarion_bartlett.cfb_estimation` implements [CFB COLT 2019](https://proceedings.mlr.press/v99/cherapanamjeri19b.html), Algorithm 1 instantiated with the efficient SDP Algorithms 4/5. It uses the 0.9*K threshold, exact span reduction, zero initialization, step size 1/20, the top eigenvector/sign rule, and returns the iterate with the smallest estimated distance. It reuses the accepted distance-search SDP solution for the gradient. A data-dependent upper radius bound replaces an arbitrary fixed search range. `tol=1e-5` controls absolute radius-search precision; the SDP residual is checked independently. `max_iter=100` means 100 iterations, and `converged=True` here means the requested finite algorithm completed, **not** an outer objective-gap or statistical-accuracy certificate. This paper is polynomial-time; the nearly-linear claim under investigation belongs to DL/PTZ.

All functions return `(estimate, info)`. The two literature functions require explicit K. They never imply that a practical K satisfies a paper's theorem. There is no hard thresholding in the new dense/literature estimators. Install `requirements.txt`; the generic SDP routines use CVXPY/Clarabel, while our estimators still require Gurobi.

```python
from non_sparse_algorithm import non_sparse_estimation
from depersin_lecue import depersin_lecue_estimation
from cherapanamjeri_flammarion_bartlett import cfb_estimation

mu, info = non_sparse_estimation(X, .1, lambda_upper, .05, seed=0, tol=1e-5)
mu, info = depersin_lecue_estimation(X, K=21, seed=0, backend="clarabel")
mu, info = depersin_lecue_estimation(X, K=21, seed=0, backend="ptz")
mu, info = cfb_estimation(X, K=21, seed=0, max_iter=100)
```

The literature methods also use K=21 for comparison. **The original guarantees do not apply here:** DL requires K>=300|O|=3000 for the ten replaced observations, and CFB's k=ceil(3200*log(1/delta))=9587 exceeds n. CFB's stated model is iid finite-covariance data, not this adaptive contamination experiment. The attack is the repository's heuristic, not a worst-case optimization. Full support means the support recovery fraction is uninformative. One n,d setting cannot establish a scaling law or confirm/refute the nearly-linear asymptotic theorem. In particular, a capped PTZ failure's runtime must not be compared as if it produced a completed estimate.
